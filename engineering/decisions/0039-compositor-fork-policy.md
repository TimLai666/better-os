# ADR 0039: How Better OS keeps its patch to `cosmic-comp`

## Status

Proposed on 2026-11-21 for the Better OS session
(`engineering/specs/better-os-session.md`), for the owner to accept or
refuse. It decides only what ADR 0038's decision C8 leaves open. C8 itself is
decided: `cosmic-comp` runs as System76 releases it first, and Better OS adds
one gesture patch, shipped as a Better OS package, once the rest of the
session works and upstream still offers nothing. Tickets 202 (the prototype)
can start without this record; tickets 223 and 226 wait on it.

## Context

The patch adds a private Wayland protocol through which Better OS's gesture
service claims swipes and pinches and drives the compositor's own workspace
switch (the contract is in the spec, "Gestures"). ADR 0038 measured what
keeping it costs: 503 commits reached `cosmic-comp`'s default branch in eleven
months, 61 of them in `src/input/mod.rs` and 34 in `src/state.rs`, the two
files the patch touches; an Epoch release came every one to three weeks; the
patch is estimated at 400 to 800 lines. Upstream's pull request template
requires the author to certify that no LLM-generated content is included, so
nothing Better OS's agents write can be offered upstream unless a person
writes it again by hand.

`cosmic-comp` is `GPL-3.0-only`. Better OS is `GPL-3.0-or-later`
(ADR 0003). Better OS's own processes only talk to the compositor over
Wayland and D-Bus. The Corresponding Source question for Better OS's own
packages is one of the four that `engineering/specs/copyleft-review.md`
leaves to the owner.

Four things are open: where the patch lives, which upstream it follows, how
its licence and source obligations are met, and when it is dropped.

## Options

### F1. Where the patch lives

- **(a) A patch series in this repository**, under `compositor/cosmic-comp/`:
  `UPSTREAM` naming the Epoch tag and commit, `patches/*.patch` applied in
  order, the protocol XML under `protocols/`, and a build script that fetches
  the tagged upstream source, checks its hash, applies the series, and builds
  the `.deb` in ADR 0021's environments. One repository, one CI, one review;
  the patch is visible as a diff against upstream.
- **(b) A fork repository beside this one** (`better-os-cosmic-comp`), with a
  branch per Epoch carrying the commits. Rebases are Git's; history is easy
  to read; but a second repository with its own CI and its own release
  process, and this repository's packaging has to fetch from it.
- **(c) A compositor built from `cosmic-comp` as a library** with
  `cosmic_comp::run(Hooks)`. The hooks cover window and stack decorations
  only (`src/hooks.rs`, "an _unstable_ interface"); input routing is not a
  hook, so this cannot carry the gesture patch.

### F2. Which upstream it follows

- **(a) Each Epoch release tag** (`pop-os/cosmic-epoch`'s tag, and the
  `cosmic-comp` commit that release names). The session's other 13 packages
  come from System76's source at the same Epoch, so compositor and daemons
  match.
- **(b) `cosmic-comp` master.** Newer fixes, and a compositor that no longer
  matches the daemons System76 released with it.

### F3. Licence and source

- The patch files and the patched compositor are `GPL-3.0-only`, as the work
  they modify; each patch file carries `SPDX-License-Identifier:
  GPL-3.0-only`. The protocol XML is Better OS's own and `GPL-3.0-or-later`;
  the GPL-3.0-only compositor may include it, because "or later" includes
  version 3.
- The rest of this repository stays `GPL-3.0-or-later`. The gesture service
  speaks the protocol over a socket and is a separate program; it is not
  affected.
- **Source offer:** every release that ships Better OS's `cosmic-comp` also
  publishes, as release assets beside its `.deb` files, the exact upstream
  source tarball used, the patch series, and the build script, with their
  SHA-256 sums, and the package's `copyright` file names that location. This
  is GPL-3.0 section 6(d)'s route (object code offered from a designated
  place, with equivalent access to the Corresponding Source through the same
  place) for this package, whatever the owner later decides for the copyleft
  review's general question.
- `docs/third-party-licenses.md` gains the compositor's crate graph from its
  own `Cargo.lock`, generated by the same script.

### F4. When the patch is dropped

- **(a) As soon as upstream offers an equivalent** that hands gesture progress
  to an outside client (a protocol or a setting), Better OS moves to it in the
  next release, puts `cosmic-comp` back on the pin's list of System76 packages,
  and deletes the series. Configurable gestures that fire an action (upstream's
  open pull requests 396, 1109, 1799, 2824, 2838, 3054) are not an
  equivalent, because none hands over progress.
- **(b) Kept regardless.** No reason found.

## Recommendation

**F1 (a), F2 (a), F3 as written, F4 (a).** The patch series in this
repository keeps one place of review and one CI; the Epoch tag keeps the
compositor matched with the daemons System76 released beside it; publishing
the source next to the binary meets the licence without waiting on the
general Corresponding Source decision.

## How a release is followed (if accepted)

1. When System76 tags an Epoch, ticket 226's closure check runs against its
   `noble` `Packages`; a release needing a package outside the closure is held
   back in Better Manager with its reason.
2. The series is rebased onto the new tag; the protocol tests and the gesture
   service's end-to-end test with the replayed recording (ticket 202) must
   pass on the rebased build.
3. Better OS releases the rebuilt `cosmic-comp` with a version that sorts
   above System76's for the same upstream (`<upstream>+betteros<n>`), and the
   pin never lists `cosmic-comp` from System76's source while Better OS ships
   it.
4. Until a rebased build passes, the session stays on the previous Epoch: the
   whole closure is held at its matching versions.

## Consequences

- Better OS rebuilds the compositor for every Epoch it takes, in both
  architectures it ships, and the session's update speed is the rebase's.
- A compositor fault in the patched build is Better OS's to find; the patch
  is small and touches input routing only, so a fault outside it is
  upstream's, reproducible on the released build.
- Nothing Better OS writes for it can go upstream, as ADR 0038 says.
