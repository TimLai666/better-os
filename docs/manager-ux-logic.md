# Better Manager UX Logic

本文件定義 Better Manager 在目前 mock lifecycle 範圍內的畫面行為。畫面只會寫入
本機版本化 JSON 狀態，不執行 APT、sudo、manifest lifecycle 字串或任何主機變更。

## 畫面與結果

| 畫面 | 顯示的狀態 | 使用者要回答的問題 | 可採取的動作 | 成功離開 | 失敗或無資料時 |
| --- | --- | --- | --- | --- | --- |
| 首次設定 | 尚未完成 onboarding | 是否以預設設定開始？ | 完成設定 | 總覽 | 無法保存時留在此畫面並顯示儲存錯誤 |
| 總覽 | catalog 與本機元件摘要 | 現在是否有需要處理的更新或健康問題？ | 開啟元件、更新或活動 | 前往所選頁面 | 沒有元件或更新時顯示空狀態 |
| 元件 | Available、Healthy、Update available、Disabled、Degraded、Failed、Restore available 或 Incompatible，以及 manifest 宣告的用途、圖示與取代或強化對象 | 這個元件下一步要安裝、更新、啟用、停用、驗證、移除，還是還原？ | 主按鈕或更多操作 | 一律先進入「檢視變更」 | 無法建立安全計畫時留在元件頁並顯示規劃錯誤；未宣告用途時顯示「未宣告」，未宣告圖示時使用通用圖示 |
| 元件詳情 | 單一元件的版本、類型、健康、更新、還原資訊，以及取代對象、強化對象與重啟需求 | 是否要檢視細節或選擇一項生命週期操作？ | 開啟分頁、停用、驗證、還原 | 詳情分頁或「檢視變更」 | 不存在的元件回到元件列表 |
| 更新 | 可更新元件與最近活動 | 是否要一次安裝全部可用更新？ | 更新全部、開啟元件 | 有更新時進入「檢視變更」 | 沒有更新時保留空狀態，不建立空計畫 |
| 檢視變更 | 已解析但尚未執行的 dry-run plan | 是否接受這次模擬變更？ | 安裝更新或套用變更，或取消 | 核准後進入「套用設定」 | 空計畫或過期計畫回到更新或元件頁並顯示錯誤 |
| 計畫項目 | 受影響元件、前後版本、相依、衝突、取代對象、強化對象、路徑、重啟需求、下載量與還原可用性；整筆交易另外顯示所有步驟中最寬的重啟需求 | 這些影響是否可接受？ | 回到上層、核准或取消 | 隨父畫面離開 | catalog 未宣告下載量或重啟需求時明確顯示「未宣告」，不猜測數字 |
| 套用設定 | Downloading、Installing、Applying settings、Checking that everything works；真實交易另外顯示實際下載位元組 | 這筆交易進行到哪裡了？還能不能取消？ | 取消（僅限尚可還原時）；示範模式另有「繼續」逐步推進 | 成功進入「完成」或「已還原」 | 取消只在下載階段提供：交易一旦交給特權服務，主機可能已經改變，此時提供取消等於承諾一個沒有人執行的還原。取消會回復完整開始前快照並回到更新；失敗會保留 stage 與 evidence 並進入復原畫面 |
| 完成 | 已通過健康檢查的非還原操作 | 是否回到總覽繼續管理？ | 回到總覽 | 總覽 | 無活動計畫時顯示規劃錯誤與返回操作 |
| 復原 | 失敗 evidence、可用快照與需要的人工處理 | 是否要還原前一個版本，或重新檢查健康？ | Restore previous version、重新檢查 | 還原成功進入「已還原」；驗證成功進入「完成」 | 部分還原或需人工復原會保留明確結果、failure evidence 與復原入口 |
| 已還原 | 已還原且已重新檢查 | 是否回到總覽？ | 回到總覽 | 總覽 | 不隱藏先前的復原活動紀錄 |
| 健康 | catalog、相容性、元件健康與可用復原資料 | 是否需要查看失敗項目或進行復原？ | 執行檢查、查看復原 | 醫生檢查結果或復原 | 有失敗項目時顯示失敗數與復原入口 |
| 醫生檢查結果 | 現行 mock 狀態的診斷結果 | 是否要再看一次或回到健康頁？ | 再次檢查、回到健康 | 健康頁或更新的結果頁 | 狀態無效時以規劃錯誤處理，不把未驗證資料當成通過 |
| 活動 | 已保存的生命週期、失敗與復原紀錄 | 是否要依類型查閱或清除紀錄？ | 篩選、清除活動 | 留在活動頁 | 無紀錄時顯示空狀態；無法保存清除結果時保留原紀錄並顯示儲存錯誤 |
| 設定 | 外觀、語言、更新偏好、篩選與 release channel | 是否要變更偏好、外觀或介面語言？ | 切換設定、外觀與語言 | 留在設定頁，外觀與語言立即更新 | 無法保存時不改變記憶體內設定與目前外觀，並顯示儲存錯誤 |

## 狀態規則

- 所有安裝、更新、啟用、停用、驗證、移除與還原都必須先經過「檢視變更」。
- 失敗發生在元件實際變更前時，只保存失敗 stage 與 evidence，不虛構可還原版本。
- 失敗發生在實際變更後時，保留開始前的快照，讓「Restore previous version」有可驗證的目標。
- 重新啟動後，進行中的 mock lifecycle 從保存的 stage 繼續，活動紀錄、失敗 evidence 與還原資料也會保留。
- 顯示的下載量、版本說明、重啟需求與磁碟需求只能來自 catalog 或未來系統執行器。現有 catalog 未提供的資料必須標示為未宣告，不能以示範值取代。
- 未宣告的重啟需求不得被降級為「不需重新啟動」。交易層取所有步驟中最寬的中斷需求。
- 元件的名稱、用途與圖示來自 manifest，或來自本版本為第一方元件內建的翻譯。不得依元件 id 猜測，也不得因為沒有內建翻譯就不顯示該元件。
- 預設外觀為深色。淺色與跟隨系統是明確的使用者選擇，與其他設定一起持久化；早於此設定的狀態檔載入為深色。
- 視窗最小支援尺寸為 720 × 540。低於偏好的 1040 寬度時 sidebar 只顯示圖示，頂端與操作列會換行，內容維持可捲動。
